# Willow agent activity feed — prepared implementation

Baseline: `wmbillock/family-website` master `64a0e5d7edbab1101ef05d9a4cf5cec47a9494ed`, read-only GitHub metadata verified October9,2026. This isolated change adds `/willow#activity`; existing default Blog and other tabs remain. No production activation or fabricated event is included. The checked-in feed is explicitly offline/empty.

## Actual code and public boundary

`Activity.jsx` fetches only same-origin `/activity/feed.json` every60seconds while visible and active, with10second timeout, abort on unmount, overlapping-request protection and bounded payload validation. Failed refresh retains prior content as historical. A successful HTTP fetch does not reset source freshness: lastSuccessAt ages independently, stale after15minutes. The UI retains evidence category/agent role/time, never claims human acceptance and never adds pretend reactions. Plain React text is escaped; no external images/links/raw HTML. Latest100events/max30days; no animation or motion dependency.

Public contract allows only schemaVersion, generatedAt, sourceObservedAt, lastSuccessAt, health, events. Each event permits an opaque digest, UTC time, finite public project label/role/action, exact deterministic summary, verification and fixed safe provenance category. There is no free prose field, private URL/path, original task/attempt/source identity, account/person data or revision field. Allowed public labels: Website, Dashboard, Creative tools, Drum project, Game project. Finance/job-search/home/health/personal categories and unknown keys fail closed. Summary strings are generated from finite templates and validated again in the browser.

`scripts/activity-projector.cjs` is a deterministic offline projection. Private policy explicitly pins each minimal source receipt's exact SHA256 and public mapping, plus a separately verified observation envelope bound to the exact source set. The observation's checkedAt advances source freshness; reprojecting cached receipts cannot advance it. Receipts later than that observation fail closed. A cached observation becomes stale after15minutes even if projection generation succeeds. Unknown pins, changed bytes, unexpected keys, unsupported category/role/action, future/invalid times or stronger verification fail closed. Replay deduplicates by source/task/attempt/revision/transition; conflicting same-identity receipts fail. Atomic write/readback and failure status preserve prior valid content/lastSuccess. No notes/logs/Console export are crawled, no programs/models are run, and no publisher is installed.

**Hashes are integrity, not authority.** This projector does not independently prove tests/deployment/review happened. A trusted source-specific adapter must first validate authoritative command/effect receipt and exact source/environment, preserve separate worker/self/independent/human judgments, verify evidence artifacts, then issue the minimal pinned receipt. Arbitrary agent messages, result prose, task `reported`, stale heartbeat or a valid JSON envelope cannot do that. Current controller source exposes task results and delivery ledgers, but a reviewed typed completion adapter/outbox is not yet integrated. No production events are admitted until this is verified.

## Existing outbound path, and exact gap

The existing website GitHub workflow on current master pushes builds CRA plus blog and uploads the full build through existing IONOS SFTP secrets. CRA copies `public/activity/feed.json` into `build/activity/feed.json`; therefore a reviewed sanitized artifact committed to website master would travel through the already established deployment path. The owner’s existing GitHub authentication supports requested repository work. No unrelated project environment credential is used, and secret values were not read. Existing workflow has `contents: read`; its scheduled blog check observes blog outputs only. It does not ingest controller events or advance this feed automatically. Private Console knowledge/snapshot credentials are not website ingestion credentials.

There is **no technical need for a new token merely to prepare this component or publish a reviewed sanitized file through the existing authorized GitHub connection**. Continuous unattended source→website delivery is still unverified. The missing pieces are (1) authoritative completion adapter/outbox, (2) same-owner recurring exporter lifetime and existing authorized GitHub transport binding for that exporter, (3) exact artifact→workflow→liveHTTPS readback. Do not copy credentials from Console/Fund or infer that interactive CLI auth automatically authorizes every new unattended service. If the existing authorized transport cannot be bound to that narrowly scoped exporter, request only the required website-repository write/dispatch connection; do not request renewed blanket public-feed publication permission, which Willow already granted. No inbound LAN exposure is needed.

## Durable outbox/integration contract

Keep private producer state outside the public website checkout. Per verified transition store stable event identity, source task/attempt/revision, exact evidence digests, typed source/verification binding, finite approved mapping, observedAt and publication state. Do not store raw messages, notes, account/person/home data or secrets. Atomic append/checkpoint before export; stable identity survives restart. Preserve unknown/uncertain effects and do not replay a provider action.

Serialize one exporter. Verify source evidence and source availability; produce strict public projection into a staged file, validate/read back hash, then advance a publication attempt tied to that exact hash. Use existing website branch/master conventions and current-source conflict checks. Never force-push or overwrite concurrent edits. A scheduled exporter that writes repository commits must prove existing auth/environment/lifetime before activation. Existing Actions serialization prevents concurrent uploads. Website build should verify `/activity/feed.json` exact hash via normalHTTPS before acknowledging published cursor. On uncertain effect, inspect same Git/Actions/livehash before retry. Publishing failure keeps private pending cursor and last successful publichash; surface generic stale/offline status without raw errors. Bounded100/30day retention applies to public artifacts; preserve private audit/effect evidence under existing domain retention rather than erase history.

The existing best-effort5minute blog cron plus frontend60second refresh is not realtime; since that cron lacks source ingestion and an activity-hash trigger, it is not currently an activity publisher. Choose and test an actual exporter cadence only after source integration; report sourceObservedAt/lastSuccess separately from display fetch.
