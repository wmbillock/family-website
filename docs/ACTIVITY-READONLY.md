# Activity feed: read-only public boundary

The public browser reads a static JSON file on the existing billock.org website. The feed renders finite text/templates only. Its one fixed request is GET /activity/feed.json, same-origin, credentials omitted, redirects rejected, referrer omitted. It has no form, command controls, callback, WebSocket, dynamic URL/image/HTML, or route to the home exporter. Streaming input is bounded to128KiB and strict schema/template validation rejects extra fields, unsupported states and forged summaries. Existing website tabs/content remain unchanged outside this component.

The private exporter makes outbound authenticated requests through existing gh state to the fixed website repository, and outbound unauthenticated GET requests to fixed billock.org HTTPS artifacts. Arbitrary public marker paths and redirects are rejected before another host can be contacted. Public data does not choose command arguments, executable paths, shell scripts, SQL statements or API write targets. The local Node subprocess executes a fixed installed projector with JSON stdin; it does not evaluate public input. SQLite statements bind values. Website credentials remain in the existing GitHub/SFTP channel; no credential values are included in the generated website or exported summaries.

There is no exporter listener, HTTP server, launchd socket, reverse tunnel, port-forward or public command endpoint. Its launch agent is an interval-triggered outbound client. The reviewed workflow remains byte-for-byte unchanged, and the build still uploads static files through existing SFTP. No new package/dependency, credential scope, firewall/router/security setting, public home address or existing-service configuration was added or changed. Listener/configuration metadata is checked separately from frontend tests. Neither a static JSON response nor CORS creates a home execution API when there is no inbound exporter endpoint.

Tests cover forged prose/URL/command/callback/HTML fields, same-origin GET/omitted credentials/redirect rejection, oversized stream cancellation, exact public-path restrictions, denied redirect targets, pending retry/conflicts, durable dedup, source freshness and exact deployed marker/feed/page/asset hashes. Synthetic hostile strings stay in tests and are never published as events. Tone changes only fixed templates: checks are checks, a reviewed interface is reviewed, a review is a review, and deployed wording is reserved for verified deployment evidence. No new actors, reactions, actions or human acceptance claims are fabricated.

Limits: this is a scoped source/runtime/public-byte audit, not a whole-site or router security guarantee. Pattern scans are not proof that every possible secret format is absent. Existing website dependency alerts remain (the reviewed npm audit reported120 including3critical/71high; package versions were unchanged). Other legacy website functionality and third-party content retain their existing behavior. The private home dashboard and other services retain existing access models; they were not reconfigured or externally penetration-tested here. External ingress/NAT rules were not independently scanned. The website host and existing GitHub channel remain trusted publication infrastructure; a compromised whole website can replace its own JavaScript. No new security grants are requested for this fix.

Rollback: stop only com.willow.billock-activity-feed, preserve its private outbox, restore the prior installed scripts/contract and revert the additive tone/hardening commit while retaining intervening edits. Public template and exporter contract must match. Keep a reviewed offline/empty feed through the stable public path if withdrawing; SFTP deletion is not assumed. Restore only the dedicated feed launch agent when validated.
